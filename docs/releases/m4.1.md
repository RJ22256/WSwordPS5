**WSword PS5 - milestone 4, fix 1.** The game now starts on the console: the game code loads, the game's threads, file system, DLC, audio and save folder all come up. It stopped at the first time it asked for the local date (for the save's timestamp).

- **Local time:** fixed. A PS5 title's C library has no time zones, so asking for the local time gave a time with no zone name, and WSword crashed reading that name. The local time now comes from the console's own settings: its time zone and summer time.
- **Crash reports:** they now name WSword's functions, read from `WSword.sym` beside `eboot.bin`. Before this they showed `?`.
- **Game files on an external drive:** the `extracted` folder can now be on a USB drive or extended storage instead of in the title folder. WSword looks in these places, in order, and uses the first one that has the game:
  1. a full path written as the first line of `game-files.txt` in the title folder (e.g. `/mnt/usb0/Games/extracted`)
  2. the title folder's own `extracted` folder
  3. on each USB drive (`/mnt/usb0` to `usb7`) and extended storage drive (`/mnt/ext0` to `ext2`): `WSword/extracted`, `PPSA99777/extracted` or `extracted`

  The log's `[ps5] game files:` line says which one it used. `swgame.so` and `swgame.so.id` stay in the title folder.
